# 셀러도어 · 와인 직구 최적경로 플랫폼

와인을 고르면 **와이너리 직배송 · 현지 수출 리테일러 · 현지 배송대행지 · 홍콩 경유** 네 경로의 운임과 관세·주세·교육세·부가세를 모두 더한 **한국 도착가**를 계산해 가장 싼 경로를 추천하고, 해당 판매처로 연결하는 비교 플랫폼입니다.

> 플랫폼은 와인을 팔지 않고 비교·연결만 합니다. 결제와 주문은 소비자가 해외 판매처에서 직접 하고, 플랫폼은 제휴 링크 수수료를 받습니다. (기획안 「법규 검토」)

## 주문 흐름

셀러도어는 결제·주문을 대신하지 않습니다(구매대행 구조 회피). 대신 손님이 판매처에서 결제만 하면 되도록 준비합니다.

1. **주문서 정보 한 번 저장** (`/me#profile`): 영문 이름·주소, 휴대폰, 개인통관고유부호. 통관부호는 AES-256-GCM으로 암호화 저장(`ORDER_DATA_KEY`). 운영에서 `ORDER_DATA_KEY`와 `SESSION_SECRET`이 모두 없으면 통관부호 저장을 거부합니다. 별도 암호화 키를 설정해 사용하세요.
2. **이 경로로 주문하기** (`/order/[offerId]`): 예상 도착가, 주의사항, 판매처 주문서 칸 순서대로 정리한 값과 복사 버튼.
3. **결제 화면 열기** (`/go/[offerId]`): 클릭 기록 → 로그인 손님은 주문 추적 시작 → 판매처 방식에 따라 이동
   - `SHOPIFY_CART`: `/cart/{variant}:{수량}`로 장바구니에 담고 이메일·영문 배송지·전화·주문 메모(통관부호)를 미리 채움. 판매 정보에 variant ID 필요.
   - `CART_TEMPLATE`: 판매처별 URL 템플릿 (`{url} {ref} {qty} {clickId} {email} {note}`)
   - `PRODUCT_PAGE`: 상품 페이지(제휴 링크)
   - 배송대행지 경로는 배대지 주소로 받아야 하므로 한국 주소를 채우지 않습니다.
4. **주문 진행 추적** (`/me#orders`, `/admin/orders`): 판매처로 이동 → 주문 확정 → 발송 → 통관 중 → 도착
   - 판매처 포스트백 `status=confirmed|shipped|delivered|cancelled` (+ `order`, `carrier`, `tracking`)으로 자동 변경, 손님에게 알림톡(`SOLAPI_TEMPLATE_ORDER_STATUS`, 변수 `#{와인} #{상태} #{판매처} #{링크}`) 또는 이메일
   - 상태는 앞으로만 진행 (늦게 온 포스트백이 되돌리지 않음)
   - 포스트백 없는 판매처: 손님이 "결제 완료했어요 / 통관 중 / 받았어요"를 누르거나 관리자가 변경
   - "받았어요"에 실제 세금을 넣으면 구매 기록이 자동으로 생겨 도착가 오차 지표에 반영

## 고객 편의 기능 · 1차

2026년 10월 2일 기획안의 1차 범위인 **통관·배송 한 화면 추적**과 **첫 직구 도우미**를 추가했습니다. 장바구니 합산 시뮬레이터·신뢰도 점수 개편·계절 경고·파손 대응·음용 적기 알림은 이 추가 작업의 범위에 포함하지 않습니다.

### 통관·배송 한 화면 추적

- `/me#orders`의 내 주문에서 `/tracking/[id]` 상세 화면을 열고 운송사와 운송장 번호를 등록합니다. H B/L 번호가 운송장과 다르면 별도로 입력할 수 있습니다.
- 해외 배송 → 한국 도착 → 통관 → 세금 고지 → 국내 배송 → 수령 완료의 6단계와 실제 확인된 단계의 통과 시각을 표시합니다. 확인되지 않은 단계와 예상 도착일은 임의로 만들지 않습니다.
- 세금이 확인되면 원화 금액, 주문 시 예상액과의 차이, 공식 납부 안내를 표시합니다. 셀러도어가 세금을 대신 받거나 납부하지는 않습니다.
- 수령한 주문의 후기 링크는 와인·판매처·경로·실제 세금·배송일을 미리 채웁니다. 실제 세금이 확인되지 않은 경우 고객이 확인해 입력합니다.
- 자동 조회는 아래 정규화 배송 게이트웨이를 연결한 경우에만 동작합니다. 게이트웨이 미설정·조회 실패 시에는 현재 기록과 공식 운송사·관세청 조회 링크, 고객의 수동 진행 확인을 제공합니다.

**연동 구조:** 고객 화면 → 셀러도어 배송 동기화 → 정규화 게이트웨이 → 해외 운송사·관세청·국내 운송사. 현재 DHL·FedEx·UPS·EMS나 관세청 API에 대한 직접 연동 또는 공급자 계약이 완료된 상태는 아닙니다. 공식 조회 링크와 자동 데이터 연동은 구분합니다. 운영자는 공급자를 선택하고 이용 조건·지원 운송사·통관 매칭·요금·갱신 주기를 확인한 뒤 공통 응답을 제공하는 게이트웨이를 연결해야 합니다.

공통 데이터 검증 계약은 [`src/lib/tracking.ts`](src/lib/tracking.ts)의 `trackingPayloadSchema`입니다. 필수값은 `orderId`, 등록된 `trackingNo`, ISO 8601 `updatedAt`, `events`이며, 각 이벤트는 `stage`와 ISO 8601 `occurredAt`을 포함합니다. `stage`는 `INTERNATIONAL|KOREA_ARRIVAL|CUSTOMS|TAX_NOTICE|DOMESTIC|DELIVERED` 중 하나입니다. 이벤트의 선택값은 중복 방지용 `id`, `note`, `location`입니다. 최상위 선택값은 `stage`, `estimatedDeliveryAt`, 원화 정수 `actualTax`, `taxNoticeAt`, `domesticCarrier`, `domesticTrackingNo`입니다. 현재 단계에는 실제 이벤트가 필요하며, 늦게 도착한 데이터가 단계나 최신 메타데이터를 되돌리지 않도록 처리합니다.

**게이트웨이 요청:** 서버가 `TRACKING_API_URL`에 `POST`하며 `Authorization: Bearer <TRACKING_API_KEY>`, `Content-Type: application/json`을 보냅니다. 요청 본문은 아래 필드만 포함하며, 개인통관고유부호와 주소를 배송 게이트웨이에 보내지 않습니다. 응답의 주문·운송장 식별자는 요청과 정확히 일치해야 합니다. 운영 URL은 HTTPS여야 하며 개발용 HTTP는 localhost만 허용합니다.

```json
{
  "orderId": "셀러도어 주문 ID",
  "trackingNo": "등록된 운송장 번호",
  "carrier": "DHL",
  "customsNo": null,
  "customsYear": null
}
```

**상태 웹훅:** 게이트웨이는 같은 응답 본문을 `POST /api/tracking/webhook`으로 보낼 수 있습니다. `X-Tracking-Timestamp`에는 Unix 초를, `X-Tracking-Signature`에는 `sha256=<16진수 HMAC-SHA256>`를 넣습니다. 서명 대상은 `timestamp + "." + 정확한 원본 JSON 본문`이며 키는 `TRACKING_WEBHOOK_SECRET`입니다. 시각은 서버 기준 ±5분 이내여야 하므로 재전송 시 새 시각과 서명을 사용합니다. 웹훅과 폴링에서 동일 이벤트가 들어와도 중복 기록하지 않습니다. 요청·응답은 최대 64KiB, 이벤트는 최대 100개이며 자동 조회는 주문당 5분 간격을 둡니다.

### 첫 직구 도우미

- 경로 비교에서 처음 구매 준비를 시작하면 `/guide/first`가 열립니다. 이후에도 가이드에서 다시 열어 이어서 준비할 수 있습니다.
- 회원가입·성인인증, 개인통관고유부호 발급, 해외결제 카드 확인, 영문 주소 준비, 선택 경로별 준비, 주문 후 운송장 등록의 6단계를 안내합니다. 로그인 회원의 체크 상태와 경로별 준비 상태는 다음 방문에도 유지됩니다.
- 단계마다 자주 묻는 질문 3개와 공식 안내 링크를 제공합니다. 배대지는 가입·주소 발급을, 직배송은 판매처 주문 폼과 주소 입력을 안내합니다.
- `JUSO_API_KEY`가 있으면 도로명주소 안내시스템의 공식 영문 주소를 검색해 선택합니다. 키가 없거나 조회에 실패하면 공식 사이트에서 확인한 영문 주소를 직접 입력합니다. 상세 주소·수령인 이름은 고객이 확인합니다.
- 개인통관고유부호는 발급 완료만 체크하고 저장하지 않아도 됩니다. 저장을 선택하면 기존 주문서 정보의 AES-256-GCM 암호화 저장을 사용하며, 도우미 진행 기록에는 통관부호를 저장하지 않습니다. 운영에서는 별도의 `ORDER_DATA_KEY`를 설정합니다.

**관리 지표** (`/admin/growth`): 최근 30일 생성된 구매 확인 주문의 운송장 등록률(목표 40%), 최근 30일 수령한 추적 주문의 후기 작성률(30%), 최근 30일 시작한 도우미의 완료율(60%), 도우미 시작 후 첫 구매 확인 회원 비율과 평균 소요일을 보여줍니다. 단순 판매처 이동과 취소 주문은 구매 확인에서 제외하고, 고객이 확인한 주문도 포함합니다. 분모·분자와 집계 기준을 화면에 표시하며 기록이 없으면 `-`입니다. 고객 문의 데이터는 연결되어 있지 않아 "배송 어디쯤" 문의 비율은 집계하지 않습니다.

## 회원 데이터 · 동의 · 세그먼트 (2026-10-03 추가)

기획안 「소비자 DB 설계」를 사이트에 옮긴 부분입니다. 소득·자산은 받지 않고, 확정 주문의 병당 도착가와 선택 설문만 씁니다.

- **국내 미유통 와인만 보기** (홈 검색 필터, `?notkr=1`): 국내 판매가가 없는 와인만 모아 보며, 이때 기본 정렬은 도착가 낮은 순입니다. `src/app/page.tsx`

## AI 직구 상담 · 1차

`/consultation`과 화면의 상담 버튼에서 **세금과 직구 절차**를 질문합니다. 로그인하고 만 19세 이상 성인인증을 완료한 회원이 이용할 수 있습니다. 무료 회원은 한국 시간(KST) 하루 5회, 프리미엄 회원은 횟수 제한 없이 이용합니다. 추천·음식 페어링·파손 상담은 후속 단계이며 이번 1차에서는 제공하지 않습니다.

- 와인과 구매 수량·용량 등 계산 조건을 선택하고 세금이나 준비 절차를 질문합니다. 조건이 부족하면 추가로 확인할 항목을 안내합니다.
- 모델은 질문 의도를 구조화하는 데만 사용합니다. 세액·가격·운임과 답변 문구는 저장된 판매 정보·환율·세율과 기존 세금·경로 계산기로 만듭니다. 모델이 임의로 만든 금액이나 세율을 답변에 쓰지 않습니다.
- 답변에서 경로 비교·직접 계산기·첫 직구 도우미와 공식 통관 안내로 이동할 수 있습니다. 세금과 도착가는 현재 저장된 데이터에 따른 예상치이며, 실제 과세환율·원산지 증빙·운임·통관 판단에 따라 달라질 수 있습니다.
- `ANTHROPIC_API_KEY`가 없거나 모델 호출에 실패하면 플랫폼 계산기와 기본 절차 안내로 답변하고 **AI 미사용**을 표시합니다. 모델 사용 여부와 계산 결과의 근거를 화면에서 확인할 수 있습니다.
- 탈세·허위 신고·개인 간 거래·음주 권장 등 지원하지 않는 요청은 거부합니다. 개인통관고유부호·이메일·전화번호·카드번호 등 민감한 개인정보가 감지되면 질문을 DB에 저장하거나 외부 모델 API에 보내기 전에 차단합니다. 상담 입력칸에 주문서 개인정보를 넣지 않습니다.

**설정과 보관:** 기존 라벨 인식과 같은 `ANTHROPIC_API_KEY`를 사용합니다. 상담 분류 모델은 `CONSULTATION_MODEL`로 선택하며 기본값은 `claude-haiku-4-5-20251001`입니다. 상담 질문·구조화 답변·모델 사용 여부·토큰 수·피드백·연결 클릭 기록은 `CONSULTATION_RETENTION_DAYS`에 따라 기본 30일 보관하며, 설정값은 1~365일 범위로 제한합니다. `consultation-cleanup`은 `expiresAt`이 지난 상담과 같은 보관 기간보다 오래된 일별 이용량 기록을 삭제합니다. 운영 시 DB 마이그레이션, 성인인증 설정, 정기 삭제 작업을 적용하고 실제 판매 정보와 세율·환율을 확인합니다.

**상담 API:** `GET /api/consultation`은 본인의 만료되지 않은 최근 상담 최대 10개와 남은 횟수를 반환합니다. `POST /api/consultation`은 `message`(1~1,000자), 선택값 `wineId`, `qty`(1~24), `bottleMl`(375·750·1,500), 후속 질문의 `previousId`를 받습니다. 응답에는 상담 `id`, `answer`(종류·본문·링크·계산 카드), `remaining`(프리미엄은 `null`), `aiUsed`, `expiresAt`가 있습니다. 요청 본문은 최대 16KiB입니다. 로그인 필요는 401, 성인인증 필요는 403, 잘못된 입력·민감 정보 감지는 400, 본문 초과는 413, 무료 한도 초과는 429, 일시 장애는 503입니다. `POST /api/consultation/[id]/feedback`의 `helpful` 또는 `action=compare|watch`는 본인 상담의 피드백·연결 클릭만 기록하며 주문이나 찜을 대신 생성하지 않습니다.

**관리 지표** (`/admin/growth`): 최근 30일에 생성되고 아직 만료되지 않은 상담의 이용 회원·응답 수, 긍정 평가율(평가한 응답만 분모), 경로 비교·찜 링크 클릭률(응답당 각 1회)을 표시합니다. 찜 링크 클릭은 실제 찜 등록과 구분합니다. 입력·출력 토큰 중 하나라도 사용량이 기록된 응답의 평균 토큰 수에는 모델 응답 검증 실패 후 기본 안내로 전환한 경우도 포함합니다. 토큰 수를 원화 비용으로 환산하지 않으며 실제 요금은 사용 모델·공급자 요금표·계약 조건으로 별도 확인합니다.

첫 구매 확인율 비교의 공통 대상은 집계 기간 시작 전에 가입·성인인증을 완료하고 이전 구매 확인이 없는 회원입니다. 기간 중 유효한 상담 기록이 있는 집단은 첫 상담 이후 첫 구매가 확인된 비율을, 유효 상담 기록이 없는 집단은 같은 기간 중 첫 구매가 확인된 비율을 비교합니다. 구매 확인은 취소·단순 이동 주문을 제외한 주문 상태 이벤트와 제휴 전환 기록의 최초 시각을 사용하며 고객의 수동 확인도 포함합니다. **유효 상담 기록 없는 집단 대비 1.5배는 관측 지표의 목표**이고, 그 집단의 구매 확인이 0건이면 배수는 `-`입니다. 이 값은 결제 검증이나 상담의 인과 효과를 뜻하지 않습니다. 만료·삭제된 상담 사용 이력은 사용 여부 구분에 포함되지 않습니다. 접속 빈도·상담 시점을 통제하지 않으며, 보관 기간에 따라 집계 대상도 달라집니다.

상담의 세금 숫자 오류 0건은 **주간 수동 검수 목표**입니다. 자동 오류 판정이나 검수 완료를 뜻하는 지표는 아직 없습니다.

- 사진 속 가격이 읽히면 그 가격과 직구 도착가를 비교하고, 국내가가 더 싸면 국내 구매를 권합니다. 목록에 없으면 "구해주세요" (미수입 와인 수요 리스트).

**성장 지표** (`/admin/growth`): 찜 회원 재방문율(비찜 대비), 알림 클릭률, 알림 경유 주문, 찜 한도→프리미엄 전환, 카드 저장률, 카드 경유 가입 비율, 공유자당 유입, 첫 후보 정답률, 사진 검색 회원 찜 수, 구해주세요 중 사진 경유 비율.

## 커뮤니티 (1단계: 직구 인증 후기 + 랭킹)

목적은 체류시간이 아니라 경로 데이터 정확도입니다. 후기 1건 = 실제 경로 1건의 검증된 비용 기록.

- **직구 인증 후기** (`/community`, `/community/write`): 경로·실제 세금·배송일(필수), 파손 여부, 별점, 한 줄 평, 카드 청구액(선택). 내 주문에서 쓰면 와인·경로·판매처·세금·배송일이 자동으로 채워집니다.
  - 통관 내역·영수증 사진 → 운영자 확인 → **통관 인증** 배지. 사진은 운영자·작성자만 볼 수 있고 확인 즉시 삭제.
  - 와인 상세 경로마다 **실측**(후기 수, 실제 배송 평균, 실제 세금의 예상 대비 오차)이 붙고, 판매처 신뢰 점수도 후기로 계산합니다.
  - 주문 없이 쓴 후기도 관리자 지표 "도착가 오차"에 들어갑니다.
- **랭킹** (`/community/ranking`): 이번 주 많이 담긴 와인, 실측 절약액 큰 경로, 이달의 후기왕(후기 1점·인증 +2점·도움됨 10개당 1점). 협찬 후기는 절약액·후기왕 랭킹과 판매처 신뢰 점수에서 제외합니다. 도움됨 집계는 실제 회원별 반응 기록으로 계산합니다.
- **포인트**: 후기 300P, 인증 +500P, 도움됨 10개마다 +200P, 종료된 월의 후기왕 최대 3명에게 프리미엄 1개월. 본인 후기에는 도움됨을 누를 수 없고, 취소 후 재클릭으로 같은 10개 구간을 다시 넘어도 한 번만 보상합니다. 협찬 후기에는 도움됨 포인트를 지급하지 않습니다. 사용처는 프리미엄 구독(3,000P = 1개월)뿐이고 와인 값에는 쓸 수 없습니다. 차감·기간 연장과 월별 보상 기록·기간 연장은 각각 같은 트랜잭션으로 처리합니다. 오픈 첫 달 배수는 관리자 설정.
- **운영 정책** (`/community/rules`)
  - 휴대폰 본인인증(PortOne V2)으로 만 19세 이상만 글쓰기·도움됨·신고. 본인인증 연계정보 해시로 1인 1계정.
  - 판매·양도·나눔·공동구매 모집·연락처·음주 권장 표현은 자동 차단 (관리자 화면에서 패턴 편집).
  - 신고 즉시 공개 목록에서 제거 → 운영자 확인 후 복구/최종 삭제. 신고도 성인인증·닉네임 설정이 필요합니다. 대가성 후기 미표시가 확인되면 판매처 노출 중단 버튼.
  - 협찬 후기는 "광고·협찬" 표시, 랭킹·신뢰 점수에서 제외.
- **초기 콘텐츠**: 관리자 화면에서 초대 코드 발급 (초기 회원 배지 + 프리미엄 N개월), 포인트 배수 기간 설정.
- **단계 관리** (`/admin/community`): 1단계 KPI(이달 신규 후기, 이달 수령 주문 중 후기 작성률), 인증·신고 대기열, 후기왕 보상 지급, 2단계를 여는 기준(후기 수·회원 수, 가안) 진척도. 통관 인증은 자료가 남아 있는 심사 대기 후기에만 승인할 수 있고, 승인·사진 삭제·인증 포인트는 함께 처리합니다.
- 2단계(마이 셀러, 구해주세요, 등급·뱃지)와 3단계(페어링, 오프라인 시음)는 기준에 도달하면 붙입니다.

## 계산 규칙

`src/lib/tax.ts` · 세율 값은 관리자 화면에서 바꿉니다.

| 조건 | 관세 | 주세 | 교육세 | 부가세 | 합계 (과세가격 대비) |
| --- | --- | --- | --- | --- | --- |
| 1병 · 1L 이하 · 물품가 150달러 이하 | 면제 | 30% | 주세의 10% | 면제 | 33.0% |
| 그 외 + FTA 원산지 국가에서 구매 | 0% | 30% | 주세의 10% | 10% | 46.3% |
| 그 외 + 제3국(홍콩 등)에서 구매 | 15% | (가격+관세)의 30% | 주세의 10% | 10% | 68.2% |

- 과세가격 = 물품가 + 한국까지 국제운임. 세액은 원 미만 절사, 합계 1만원 미만은 징수 면제.
- FTA는 **원산지 국가 판매처에서 산 경우에만** 적용합니다. 홍콩 경유는 항상 제외, 아르헨티나처럼 FTA가 없는 원산지는 모든 경로에 관세가 붙습니다.
- 배송대행지 경로 = 원산지 국가 판매처 가격 + 판매처→배대지 운임 + 배대지→한국 운임. 주류를 받지 않는 배대지(미국·칠레 등)는 이유와 함께 제외됩니다.
- 운임은 셀러별 `기본료 + 병당 요금 × 750ml 환산 병 수`입니다.

## 실행

필요: Node 22, PostgreSQL 16

```bash
cp .env.example .env          # DATABASE_URL, ADMIN_EMAILS 등 수정
npm install
npx prisma migrate deploy
npm run db:seed               # 예시 데이터 (와인 16종, 셀러 22곳, 배송대행지 6곳)
```

## 정기 작업

| 작업 | 주기 | 내용 | 수동 실행 |
| --- | --- | --- | --- |
| `fx` | 1시간마다 | investing.com 통화쌍 시세(USD/KRW, EUR/KRW …)를 받아 즉시 반영. 못 받은 통화는 수출입은행으로 보충하거나 직전 값 유지 | `npm run job:fx` |
| `alerts` | 수집 직후 (6시간마다) | 찜별 도착가 기록 → 목표가 도달·5% 하락·재입고 알림 | `npm run job:alerts` |
| `digest` | 월요일 아침 | 무료 회원의 대기 알림을 한 통으로 | `npm run job:digest` |
| `crawl` | 6시간마다 | 수집 방식이 JSON-LD인 셀러의 상품 페이지에서 가격·재고 갱신 | `npm run job:crawl` |
| `tracking` | 1시간마다 | 운송장을 등록한 진행 중 주문의 정규화 배송·통관 상태 동기화 | `npm run job:tracking` |
| `consultation-cleanup` | 매일 09:32 KST | 보관 기한이 지난 상담 기록과 오래된 일별 이용량 기록 삭제 | `npm run job:consultation-cleanup` |

운영에서는 스케줄러가 `GET /api/cron/{fx|alerts|crawl|digest|tracking|consultation-cleanup}`을 `Authorization: Bearer $CRON_SECRET`로 호출합니다. `.github/workflows/jobs.yml`이 이 역할을 하며, 저장소 Secrets에 `APP_URL`·`CRON_SECRET`, Variables에 `JOBS_ENABLED=true`를 넣으면 켜집니다. 배송 추적은 매시 22분, 상담 기록 삭제는 `32 0 * * *`(UTC, 매일 09:32 KST)에 호출합니다. 게이트웨이 설정이 없으면 자동 추적 작업은 데이터를 생성하지 않고 건너뜁니다.

## 환율 (investing.com)

- 관리자 › 세율·환율에서 출처(investing.com / 수출입은행), 보충 여부, 급변 차단 기준(기본 10%)을 정합니다.
- investing.com은 공식 API가 없어 통화쌍 페이지(`/currencies/usd-krw` 등)의 현재가를 읽습니다. 파서는 세 가지 표기를 순서대로 시도합니다 (`src/lib/investing.ts`).
- 받은 시각과 출처가 와인 상세·계산기 화면에 표시됩니다.
- **주의**: investing.com 이용약관은 자동 수집을 제한하고, 서버에서 보내는 요청은 봇 차단(HTTP 403)될 수 있습니다. 운영 전에 배포 서버에서 `npm run job:fx`로 실제 수신 여부를 확인하고, 상업적 이용 허가나 유료 시세 API 전환을 검토하세요. 수신이 안 되면 수출입은행 보충이 자동으로 동작합니다.
- 실제 세금은 관세청 주간 과세환율로 매겨지므로, 시세 기준 도착가와 약간 차이가 날 수 있습니다.
